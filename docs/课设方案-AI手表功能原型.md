# 课设方案：云边端协同 AI 手表功能原型

- 对应指导书：题目 2《基于 STM32 微控制器的智能系统设计》
- 定位：普中 PZ6808L-F4 上的**多功能 AI 手表原型**（LVGL 表盘、传感器环境量、语音上云、通知），不是可穿戴成品
- 原则：F407 做界面、采集和本地环境量；ESP32-C3 把语音和请求送上云，再把云端消息送回；重识别在云端。F103 本阶段不开发
- 硬件依据：`1--用户必看/普中PZ6808L-F4开发板入门教程.md`、`tmp/sch/out/STM32F407-PZ6808L开发板原理图.md`、`tmp/sch/out/TFT3.5-ILI9486彩屏原理图.md`，以及原理图分区截图（按键、LED、蜂鸣、MPU6050、232、WIFI 座、TFT 座、CH340、晶振）

文中用两种标记，写报告时不要混用：

| 标记 | 含义 |
| --- | --- |
| 【板级事实】 | 原理图网表或入门教程上能指到的连接、位号、阻值 |
| 【方案约定】 | 本方案为了能做完课设规定的参数（波特率、帧、阈值、像素）。上板后可以改，改了要在报告里写实测值 |

设计基准屏：3.5 寸 HX8357，320×480，RGB565，FSMC 16 位。座子与资料里的 ILI9486 模块相同，都是 34P；初始化必须用 HX8357 的表，不能套 ILI9486。下文像素按 320×480 写。

## 1. 目标与范围

### 1.1 要交什么

一套能演示的系统，同时满足指导书四项：

| 要求 | 本方案 | 落在哪颗芯片 |
| --- | --- | --- |
| 数据采集 | 模拟麦克风、MPU6050、DS18B20、板载四键 | 全在 F407 |
| 本地处理/控制 | 计步、表温、跌倒粗判、录音组包、把云端文字变成动作 | 全在 F407 |
| GUI | HX8357 上的 LVGL 表盘 | F407 + FSMC |
| 云端交互 | 语音与天气请求上去，文本消息回来 | ESP32-C3 |

### 1.2 必交（MVP）

1. LVGL 表盘先跑起来：时间、计步、表温、联网状态。秒针或翻页用局部动画，刷新周期 16 ms；整屏不承诺 60 Hz
2. 环境量全部在 F407 上算完：MPU6050 计步（自写阈值，不用 DMP）、DS18B20 表温、可选的跌倒粗判。这些不上传原始波形
3. 语音：按住 K_UP 录音，F407 组好 PCM，经 UART4 交给 C3；C3 补 WAV 头后送给云端识别；云端返回的文字再经 C3 回到表盘
4. 至少一条本地指令：「开灯 / 关灯」，点 F407 的 LED1（PF9，低电平亮）
5. 一条云端应用：查天气，C3 拉 Open-Meteo，表盘显示一行中文摘要
6. 断网后表盘、计步和表温仍走。语音页给出未联网，用来说明识别在云、环境量在板子上

### 1.3 加分

7. 跌倒粗判 → C3 上报一条告警，屏切到通知页，蜂鸣器短响
8. RTC 闹钟到点，F407 驱动板载蜂鸣器

### 1.4 本阶段不做

- 真表外形、续航、表带
- 心率血氧、植物医生、科学计算器
- 在 STM32 或 C3 上做离线语音模型、图像识别
- 让 C3 刷屏、采 MPU、跑计步
- 小游戏。LVGL 和前面的语音、环境量都做完之后再单独商议
- 烧录 F103。只有 F407 在界面和采样同时跑时实测来不及，才按 3.9 启用
- 不使用板载以太网、RS485、CAN、NRF24L01、摄像头、TF 卡、ESP8266 座

## 3. 板级事实与连接

### 3.1 时钟、存储、电源

【板级事实】

| 项目 | 位号 / 网络 | 报告里可写的参数 |
| --- | --- | --- |
| 主控 | U? STM32F407ZGT6 | Cortex-M4F，教程给出 1024 KB Flash、192 KB SRAM、FPU/DSP |
| 高速时钟 | Y3，PH0/PH1 | 图上标 **8 MHz**，负载电容约 22 pF |
| RTC 时钟 | Y4，PC14/PC15 | **32.768 kHz**，负载电容 10 pF（C80/C81） |
| 后备电池 | VBAT，模块 43 | 纽扣电池只养后备域和 RTC，主电源断开后时钟继续走 |
| 外部 SRAM | U13 IS62WV51216 | 512K×16 = 1 MB，片选 FSMC_NE3 = PG10，基址 `0x68000000` |
| SPI Flash | U9 EN25Q128 | 16 MB，SPI1：CS=PB14，SCK=PB3，MISO=PB4，MOSI=PB5。与 JTAG 的 TDO/TRST 复用，SWD 调试只用 PA13/PA14，这四根仍可作 SPI |
| EEPROM | U18 24C02 | 256 字节，与 MPU6050 共用 I2C1。E0=E1=E2=GND，7 位地址 **0x50** |
| 3.3 V | V2，教程模块 3 | 5 V 经稳压到 3.3 V。火牛口 P8 **不得超过 5 V** |
| 对外电源 | P9 | 5 V、3.3 V、GND 排针。C3 从这里取 **3.3 V + GND** |
| 系统复位 | NRST 网络 RSET | TFT 座的 RESET 与 MCU 复位连在一起，没有单独的 LCD 复位脚 |

【方案约定】时钟树（与 8 MHz 晶振对齐，供报告画 PLL）：

- HSE = 8 MHz，PLL：M = 8，N = 336，P = 2 → SYSCLK = **168 MHz**
- AHB = 168 MHz，APB1 = 42 MHz，APB2 = 84 MHz
- APB1 分频不为 1 时，挂在 APB1 上的定时器时钟 ×2 = **84 MHz**。后面 16 kHz 采样用这个数，可以整除

### 3.2 F407 本方案占用的引脚

【板级事实】网络名来自结构化网表；复用功能号（AF）是 STM32F407 数据手册的对应项，写驱动时用。

| 功能 | MCU 引脚 | 网络名 | 模式 | 电气极性 / 地址 |
| --- | --- | --- | --- | --- |
| 时间 | RTC，PC14/PC15 | OSC32 | LSE | 见 3.1 |
| 蜂鸣器 BZ1 | PF8 | BEEP | 推挽输出 | 三极管 TP6 发射极接 +3.3 V（PNP 高边），基极串 R06 = 470 Ω，R66 = 10 kΩ 上拉。**PF8 低电平鸣叫**；复位期间引脚高阻，10 kΩ 保证默认不响。上板听一声确认，若反了只改宏 |
| LED1 | PF9 | LED1 | 推挽输出 | D1 阴极接 MCU，阳极经 R97 = 10 kΩ 到 3.3 V。**低电平亮**。10 kΩ 电流约 0.1 mA，灯很暗，演示时凑近看 |
| LED2 | PF10 | LED2 | 推挽输出 | 同 LED1，R98 = 10 kΩ，低电平亮。MVP 可留作“识别中”指示 |
| K_UP | PA0 | KEY_UP | 输入、下拉 | 按下接 +3.3 V，**高电平有效**，可作 WKUP。本方案用它做“按住说话”，不进待机 |
| K_RIGHT（丝印 K1） | PE2 | K1 | 输入、上拉 | 按下接地，**低电平有效** |
| K_DOWN（丝印 K2） | PE3 | K2 | 输入、上拉 | 低电平有效 |
| K_LEFT（丝印 K3） | PE4 | K3 | 输入、上拉 | 低电平有效 |
| MPU6050 SCL | PB8 | IIC_SCL | I2C1，AF4 | 开漏，板上 R53 = 10 kΩ 上拉 |
| MPU6050 SDA | PB9 | IIC_SDA | I2C1，AF4 | 同上。AD0 接 GND，7 位地址 **0x68**，WHO_AM_I（0x75）应读回 0x68 |
| MPU 中断 | PC0 | 3D_INT | 输入 | INT 经 R3 = 1 kΩ 到 PC0。MVP 轮询，不挂 EXTI |
| DS18B20 DQ | PG9 | 18B20 | 开漏 | 座子 DS1：1=GND，2=DQ，3=3.3 V；R54 = 10 kΩ 上拉。凸点对齐丝印。此脚同时是摄像头 DCMI_PWDN，本方案不插摄像头 |
| 模拟麦克风 | PA5 | STM_ADC | ADC1_IN5 | 见 3.4 |
| 接 C3 | PC10 | SDIO_D2 | UART4_TX，AF8 | 见 3.5 |
| 接 C3 | PC11 | SDIO_D3 | UART4_RX，AF8 | 见 3.5 |
| 不用 | PB10 / PB11 | USART3 | 保持默认 | 接到 RS232 和 ESP8266 座，本方案不使用 |

### 3.3 四键在本方案里的分工

【方案约定】

| 键 | 表盘页 | 语音页 | 通知页 |
| --- | --- | --- | --- |
| K_LEFT / K3 | 上一页 | 上一页 | 上一页 |
| K_RIGHT / K1 | 下一页 | 下一页 | 下一页 |
| K_UP / PA0 | 按住开始录音，松开或满 3.0 s 结束 | 同左 | 同左 |
| K_DOWN / K2 | 无 | 重发上一包音频 | 清除告警显示 |

扫描周期 10 ms，消抖 20 ms。K_UP 按下短于 400 ms 视为误触，丢弃，不上传。

### 3.4 麦克风怎么接到 PA5

【板级事实】ADC 区有两排跳线：

- J01：1 = STM_ADC（PA5），2 = R_ADC（电位器 AD1 的滑臂），3 = GND。把 1-2 短上，PA5 采的是板载电位器
- J4：1 = 电容触摸 P_TOUCH，2 = STM_DAC（PA4），3 = STM_ADC（PA5），4 = PWM_AUDIO

【方案约定】必交用**模拟麦克风模块**（驻极体模块或 MAX9814 一类，输出 0～3.3 V 的模拟声）：

1. J01、J4 的短路帽全部拔掉，避免电位器、触摸、DAC、PWM 音频和麦克风并联
2. 模块 VCC → P9 的 3.3 V，GND → P9 的 GND，AO → 排针上的 PA5
3. 采样：**16 kHz，12 位 ADC，单声道，最长 3.0 s**
4. 触发定时器 TIM3（APB1 定时器时钟 84 MHz）：`84e6 / 16000 = 5250` 整除，PSC = 0，ARR = 5249，TRGO 触发 ADC1
5. ADC 时钟：APB2 = 84 MHz，ADC 预分频 /4 = 21 MHz（低于 36 MHz 上限）。采样时间 84 cycle 量级即可，远短于 62.5 µs 的采样周期
6. 存成 int16 PCM：`(adc - 2048) << 4`，把中点搬到 0。静音直流偏置若偏得厉害，再在 C3 或 F407 上减一个短时均值
7. I2S MEMS 只作备选：I2S2 的 LRCK=PB12、SCLK=PB13、SDIN=PC3，这三根在排针上，且不跟 RMII 冲突。必交不走这条，避免再引入一路时钟

3 秒 PCM 长度：`16000 × 2 × 3 = 96000` 字节。

### 3.5 F407 与 ESP32-C3

【板级事实】为何不能插板载 WIFI 座（教程模块 25，位号 ESP8266WIFI）：

| 座子脚 | 丝印 | 接到 |
| --- | --- | --- |
| 1 | VCC | +3.3 V |
| 2 | URXD | 232_TXD（RS232 那一侧的 TTL 发送网） |
| 3 | GPIO16 | W_RST = PF6 |
| 4 | GPIO0 | 悬空 |
| 5 | CH_PD | W_GPIO2 = PC7（同时是 DCMI_D1） |
| 6 | GPIO2 | 悬空 |
| 7 | UTXD | 232_RXD |
| 8 | GND | GND |

这是 ESP8266 的 8 脚顺序。ESP32-C3 模组的电源、EN、UART 脚序对不上，插进去会把 C3 的 IO 接到 232_TXD/232_RXD 和 PF6/PC7 上。232_TXD/232_RXD 又是 USART3 和 SP3232 的 TTL 网。

【方案约定】C3 用杜邦线，走 F407 的 UART4：

| F407 排针 | 方向 | ESP32-C3 |
| --- | --- | --- |
| PC10（UART4_TX，AF8） | → | 接收脚。默认 UART0 的 RX 是 GPIO20 |
| PC11（UART4_RX，AF8） | ← | 发送脚。默认 UART0 的 TX 是 GPIO21 |
| P9 GND | — | GND |
| P9 3.3 V | → | 3V3 |

- 波特率 **460800，8N1，无硬件流控**。3 秒音频 96000 字节，线速率 `460800/10 = 46080 B/s`，纯载荷约 2.1 s，加上停等式 ACK 大约 3 s，答辩等得起。115200 要 8 s 以上，只在杜邦线干扰大、降速排错时用
- PC10/PC11 在板上还是 SDIO_D2/D3。**TF 卡槽留空**，卡座上的触点不会再把这两根拉住
- 同时不要初始化摄像头，PC11 还标着 DCMI_D4
- C3 用自己的 USB 下载。若手头那块 C3 板的 USB 转串口芯片已经占用了 GPIO20/21，就把 C3 侧换成 UART1（常见接法 GPIO4=TX、GPIO5=RX），F407 仍是 PC10/PC11，只改 C3 固件里的两根脚
- 供电：Wi-Fi 发射电流尖峰大约几百毫安，再叠加 TFT 背光。电脑前置 USB 口若把板子打复位，改到火牛 5 V、1 A 以上。C3 不要从 ESP8266 座取电

USART 分配（写报告用的“为什么是这一路”）：

| 串口 | 引脚 | 板上已经接死的功能 | 本方案 |
| --- | --- | --- | --- |
| USART1 | PA9/PA10 | CH340 下载，切换端子 37 | 固件不打开，留给下载和 printf 备用 |
| USART2 | PA2/PA3 | PA2 = ETH_MDIO，且进 F4 的 SP3485；PA3 = 485 的 RO | 不用 |
| USART3 | PB10/PB11 | RS232（SP3232）和 ESP8266 座 | 不用，P3/P4 不短 |
| UART4 | PC10/PC11 | 仅 SD 卡座 / 摄像头标号 | **接 C3** |
| UART5 | PC12/PD2 | SDIO_CK / SDIO_CMD，PD2 有 47 kΩ 上拉 | 不用 |
| USART6 | PC6/PC7 或 PG14 等 | PC6 是 I2S_MCLK 与 DCMI_D0；PC7 进 WIFI 座；PG14 是 RMII_TXD1 | 不用 |

### 3.6 TFT：FSMC 与 3.5 寸 HX8357

【板级事实】实际插入的屏是 HX8357，分辨率 320×480，16 位 8080 并口。主板座 U3（34P）与资料中 ILI9486 模块是同一套座子定义，网络对应关系如下：

| 信号 | F407 引脚 | FSMC 含义 |
| --- | --- | --- |
| FSMC_D0～D15 | PD14, PD15, PD0, PD1, PE7, PE8, PE9, PE10, PE11, PE12, PE13, PE14, PE15, PD8, PD9, PD10 | 16 位数据，与 SRAM 的数据线是同一组 |
| FSMC_NE4 | PG12 | LCD 片选。Bank1 子区 4，基址 **0x6C000000** |
| FSMC_A6 | PF12 | RS（命令/数据）。16 位总线下 FSMC_A[n] 对应 CPU 地址线 A[n+1]，A6 → CPU 的 A7，偏移 **0x80** |
| FSMC_NOE | PD4 | RD |
| FSMC_NWE | PD5 | WR |
| RESET | NRST | 与系统复位绑在一起 |
| T_SCK | PB0 | 电阻触摸 XPT2046 |
| T_MOSI / T_DIN | PF11 | 同上 |
| T_MISO / T_DOUT | PB2 | 同上。PB2 也是 BOOT1，只在复位瞬间采样，之后可作 GPIO |
| T_CS | PC13 | 同上 |
| T_PEN | PB1 | 模块上 50 kΩ 上拉，按下为低 |

【方案约定】

- 命令地址 `LCD_CMD = 0x6C000000`，数据地址 `LCD_DATA = 0x6C000080`
- 命令/数据地址采用普中 HAL 实验 33 的宏：`LCD_BASE = 0x6C000000 | 0x0000007E`。花屏时再改，不要同时保留两套
- FSMC 时序初值沿该例程。花屏再加大数据建立时间
- 驱动芯片定为 **HX8357D**。依据是资料里的 `2--开发板原理图/彩屏原理图/TFT3.5-HX8357D彩屏原理图.pdf` 和 `6--芯片资料/彩屏数据手册/HX8357D数据手册`。竖屏 320×480，RGB565
- **不做全屏帧缓冲**。320×480×2 = 307200 字节，内部 192 KB SRAM 放不下。开窗口后直接写 GRAM。整屏 30 Hz 只有在 FSMC 等待收到控制器允许的下限、并且循环里连续写显存时才稳，大约 20 ms 一帧；例程里偏慢的时序往往到不了 15 Hz。表盘用脏矩形，时间 1 Hz 改数字，不必整屏刷到 30 Hz
- 外部 SRAM 留着备用（大字库）。MVP 的汉字只收界面用到的约 80 个 16×16 点阵，放内部 Flash，大约 80×32 ≈ 2.6 KB
- 电阻触摸是加分，不是必交。校准四个角的结果可写进 24C02 偏移 0x20。电容屏（FT5336 等）本方案不作为交付项
- 背光在彩屏模块上经电阻接 3.3 V，主板上没有背光 GPIO，上电即亮

SRAM 与 LCD 可以同时启用：SRAM 用 NE3（`0x68000000`），LCD 用 NE4，地址线和数据线共用，靠片选区分。

### 3.8 同时用会打架的脚（写“选型依据”时用）

| PA9/PA10 | 不初始化 | CH340 | 下载口 |
| PA2/PA3 | 不用 | 以太网 MDIO、F4 的 485 | 固件保持默认 |
| PA1 | 不用 | LAN8720 的 REFCLK 输出 | 不要配成推挽去顶 PHY |
| PB8/PB9 | I2C1 | MPU6050 与 24C02 | 只作 I2C |
| PB10/PB11 | 不初始化 | RS232、ESP8266 座 | P3/P4 不短，座子空着 |
| PC10/PC11 | UART4 | SD 卡 D2/D3 | 卡槽留空 |
| PG9 | 1-Wire | 摄像头 PWDN | 不插摄像头 |
| PA5 | ADC | 电位器、J4 | 帽拔掉 |
| PF8/PF9/PF10 | 蜂鸣、灯 | 无第二功能 | 直接用 |
| PE2/PE3/PE4、PA0 | 按键 | 无 | 直接用 |
| PD8/PD9 等 FSMC 数据 | LCD + SRAM | 也是 USART3 的重映射脚 | **禁止**把 USART3 重映射到 PD8/PD9 |
| PB3/PB4/PB5/PB14 | 本阶段给 EN25Q128 或闲置 | JTAG、J2 上的 F103 SPI1 | 短接帽拔掉；调试用 SWD |

### 3.9 F103 只作为后备，本阶段不接

【板级事实】入门教程模块 33：「STM32F1 和 STM32F4 的 SPI 接口，使用短接片进行短接，可实现双机 SPI 通信。」模块 32 写明板上的 STM32F103C8T6 可与 F4 做双机通信。短接位置就是 J2：F407 的 PB15 / PB3 / PB4 / PB5 对上 F103 的 PA4 / PA5 / PA6 / PA7。

【方案约定】环境量（计步、表温、跌倒粗判）和 LVGL 都放在 F407。168 MHz 带浮点，这些运算比刷屏轻。只有做到界面、16 kHz 录音和传感器同时跑、并且测到主循环来不及时，才启用 F103：

- 下载切换拨到 F1 烧从机，烧完拨回 F4
- 短上 J2，F407 做 SPI 主机，F103 做从机
- 短上之后不要再读 EN25Q128，字库放内部 Flash 或外部 SRAM
- 从机只分担一块已经测出超时的计算，不接管屏幕、麦克风和云

这条在核心功能做完之前不动。

## 4. 功能模块

### 4.1 手机式 GUI（LVGL 8.3）

【方案约定】界面用 LVGL 8.3.11，不从 WatchX（GPL-3.0）或 phonegui（LGPL-3.0）拷源文件。第一版是手机式五页，不是圆表盘：主页为单列四行，时间、计步、天气、语音各是整页。图标只用 LVGL 自带符号（铃铛、柱状、色点、音频）。进入和返回直接换屏，焦点行立刻换强调色底，不做整屏横滑。时钟数字每秒只重画那一块。LVGL 只重画脏区域。整屏重画大约 20 ms，不把 60 Hz 写成整屏指标。

显示缓冲用两块局部行缓冲，放在内部 SRAM（`0x20000000`），以便 DMA 送到 FSMC。先用 20 行：`320 × 20 × 2 × 2 = 25600` 字节。若动画撕裂再加到 40 行（51200 字节），同时把录音从 3 秒减到 2 秒。F407 没有 DMA2D，填充和混色由 CPU 完成。`lv_tick_inc(1)` 放在 1 ms 节拍，`lv_timer_handler()` 放在主循环。

汉字仍只收录界面用字，做成 LVGL 字体，放内部 Flash。下面的像素表是控件布局，不是手写画点清单。

颜色（RGB888 → RGB565，可直接进代码）：

| 名称 | RGB888 | RGB565 | 用途 |
| --- | --- | --- | --- |
| 背景 | #0B1220 | 0x0884 | 全屏底 |
| 正文 | #E8EEF7 | 0xEF7E | 时间、识别文字 |
| 强调 | #3DDC97 | 0x3EF2 | 计步数字、在线 |
| 告警 | #FF5A5A | 0xFACB | 跌倒、识别失败 |
| 离线 | #E6B450 | 0xE5AA | 离线、上传中 |

字：ASCII 和符号用 LVGL 自带的 Montserrat 16；大时间用 Montserrat 48。界面汉字 16 像素，只收录本版出现的字。

坐标系：x 向右，y 向下，单位像素。每一页顶栏高 36：左 `HH:MM`，右「离线」。底栏在最下一行。

**主页**

| 区域 | x | y | w | h | 内容 |
| --- | --- | --- | --- | --- | --- |
| 四行列表 | 8 | 48 | 304 | 64，行距 8 | 铃铛「时间」、柱状「计步」、色点「天气」、音频「语音」 |
| 底栏 | 8 | 448 | 304 | 24 | `K1 下  K2 打开  K3 上` |

KEY_UP（PA0，高电平）上移，KEY1（PE3，丝印 K2）下移，KEY0（PE4）进入当前行。焦点行立刻换成强调色底。

**时间页**

大字 `HH:MM` 居中，下面两位秒。时间从 12:00:00 起按本地秒计数。底栏 `K3 返回`。

**计步页、天气页、语音页**

本版是空壳。计步显示 `--`，天气显示「天气 --」，语音显示「空闲」。底栏都是 `KEY2 返回`。返回后焦点留在刚才那一行。KEY2 是 PE2。不用电容触摸键。

### 4.2 计步与跌倒（MPU6050）

【板级事实】同一条 I2C 上还有 24C02，上拉已经焊好，软件开漏输出即可，不要再强推挽。VDD 与 VLOGIC 经 R5 = 10 Ω 接 3.3 V。

【方案约定】不用 InvenSense DMP，算法写在报告里能推得动。

初始化：

| 寄存器 | 地址 | 写入 | 含义 |
| --- | --- | --- | --- |
| PWR_MGMT_1 | 0x6B | 0x00 | 唤醒，时钟用内部 |
| SMPLRT_DIV | 0x19 | 19 | 陀螺仪输出 1 kHz 时，采样率 1 kHz/(1+19) = 50 Hz |
| CONFIG | 0x1A | 0x03 | DLPF 约 44 Hz，足够计步 |
| ACCEL_CONFIG | 0x1C | 0x00 | ±2 g，灵敏度 16384 LSB/g |
| INT_ENABLE | 0x38 | 0x00 | MVP 不使用中断 |

主循环每 20 ms 读一次 `ACCEL_XOUT_H`（0x3B）起的 6 字节，大端：

```
ax_g = ax_raw / 16384
ay_g = ay_raw / 16384
az_g = az_raw / 16384
mag  = sqrt(ax_g^2 + ay_g^2 + az_g^2)
```

计步：

- 慢速基线 `base = 0.98*base + 0.02*mag`，初值 1.0
- 动态量 `dyn = mag - base`
- 当 `dyn` 从大于 0.15 g 落到 0.15 g 以下，且距上一步 ≥ 300 ms，步数 +1
- 0.15 g 和 300 ms 是初值。报告里写“上板用走路/原地抖两段录音改过阈值”，把最终数字填回去

跌倒（加分，页面切到通知页）：

- `|mag| > 2.0 g` 持续不少于 2 个采样（冲击），或 `|mag| < 0.4 g` 持续 ≥ 80 ms 之后 1 s 内出现冲击
- 触发后 5 s 内不再报第二次
- 动作：蜂鸣 1 s、通知页画告警、向 C3 发 `ALERT_FALL`
- 报告里写明这是粗判演示，不是医疗器械

水平仪不做。

24C02 布局（掉电保存，可选）：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0x00 | 8 | 魔数 `WATCH` + 版本 `0x01` |
| 0x10 | 4 | 步数 uint32，小端。每增加 10 步写一次，减少擦写 |
| 0x20 | 8 | 触摸校准，未做触摸则全 0xFF |

### 4.3 语音链路

【方案约定】状态机：

```
空闲 --K_UP 按下--> 录音（ADC DMA，最多 3.0 s，松开即停）
录音 --长度≥400 ms--> 上传（UART4 分包）
录音 --太短--> 空闲
上传 --C3 收齐--> 识别中（等 ASR_TEXT，超时 8 s）
识别中 --收到文本--> 结果（屏上显示，并做关键词）
识别中 --超时/NACK--> 失败
结果 --5 s 或任意翻页键--> 空闲
```

关键词在 **F407** 上对 UTF-8 文本做子串匹配，C3 不解释语义：

| 文本包含 | 动作 | 是否上网 |
| --- | --- | --- |
| 开灯 | PF9 拉低，LED1 亮 | 识别过程已上过网；执行本身在本地 |
| 关灯 | 对应灯灭 | 本地 |
| 现在几点 | 用 RTC 在语音页写一行时间 | 本地，用来对比“识别可以在云，回答不必再请求云” |
| 查天气 | 发 `CMD_WEATHER`，等 `WEATHER_RESULT` | 再上一次网 |
| 其他 | 只显示识别文字 | 无进一步动作 |

匹配用 UTF-8 字节子串即可，「开灯」是固定的 6 字节 `E5 BC 80 E7 81 AF`。不要在 F407 上做分词。

### 4.4 天气

【方案约定】城市写成 C3 的两个宏，报告里填学校所在城市的十进制经纬度，例如：

```
CITY_LAT  31.23
CITY_LON  121.47
```

C3 请求（免密钥，便于答辩现场没有账号也能跑）：

```
GET https://api.open-meteo.com/v1/forecast
    ?latitude={CITY_LAT}&longitude={CITY_LON}
    &current=temperature_2m,weather_code
    &timezone=auto
```

把 `weather_code` 收成一行中文再经串口发给 F407，F407 不解析 JSON：

| WMO code | 显示 |
| --- | --- |
| 0 | 晴 |
| 1 | 大部晴 |
| 2 | 多云 |
| 3 | 阴 |
| 45、48 | 雾 |
| 51、53、55 | 毛毛雨 |
| 61、63、65、80、81、82 | 雨 |
| 71、73、75 | 雪 |
| 95、96、99 | 雷暴 |
| 其他 | 天气 |

显示格式固定：`多云 26°C`，摄氏度取 `temperature_2m` 四舍五入成整数。失败时 C3 回 `天气不可用`，表盘保持上一次成功的那一行。

### 4.5 表温 DS18B20

【板级事实】单总线，外部上拉是 10 kΩ（手册常见 4.7 kΩ，这是本板的阻值，线很短，能用）。只有一颗传感器。

【方案约定】不在主循环里空等 750 ms：

1. 复位脉冲 ≥ 480 µs，等存在脉冲
2. Skip ROM `0xCC`，Convert `0x44`
3. 过 750 ms 以后再总线复位，`0xCC`，Read Scratchpad `0xBE`，读前两个字节
4. 12 位分辨率，`T = raw / 16`，保留 1 位小数放到状态条
5. 转换期间 GUI 照常跑。传感器没插时，状态条写「表温 --」，不要卡死

### 4.6 RTC 闹钟（加分）

【板级事实】LSE 32.768 kHz 已焊，VBAT 有电池座。后备域在主电断开后维持日历。

【方案约定】

- 上电若备份寄存器里的魔数不对，把时间设成编译期或串口命令设一次。MVP 可在表盘用 K_DOWN 的长按进入“时/分加一”的简易对时，避免答辩时时间是 2000 年
- 闹钟比较时、分。到点 PF8 拉低 1 s，通知页写「闹钟」
- 用轮询 RTC 的时分，不必为了课设再开 RTC 闹钟中断。若开了 Alarm A，它走 EXTI 线 17

## 5. 通信协议

F407 与 C3 之间用下面这一种帧。多字节整数一律小端。

### 5.1 帧

| 字段 | 长度 | 值 |
| --- | --- | --- |
| SOF | 2 | `0xA5 0x5A` |
| VER | 1 | `0x01` |
| SRC | 1 | `0xF4` F407，`0xC3` ESP32-C3 |
| DST | 1 | 同上 |
| TYPE | 1 | 见下表 |
| SEQ | 1 | 发送方每帧 +1，应答时回显被应答的 SEQ |
| LEN | 2 | 载荷字节数，0～512 |
| PAYLOAD | LEN | |
| CRC | 2 | Modbus CRC16，多项式 `0xA001`，初值 `0xFFFF`。覆盖范围从 VER 到载荷末字节，不含 SOF |

接收：逐字节找 SOF；LEN 合法才收载荷；CRC 错回 `NACK`，错误码 `0x02`，不执行。

### 5.2 F407 ↔ C3（UART4，460800）

| TYPE | 名 | 方向 | 载荷 |
| --- | --- | --- | --- |
| 0x01 | HELLO | F4→C3 | 空。上电后每 2 s 一次，直到收到 ACK |
| 0x02 | HELLO_ACK | C3→F4 | 1 字节：0 离线，1 已连上 AP。后接 4 字节 IPv4 |
| 0x10 | AUDIO_BEGIN | F4→C3 | uint32 总 PCM 字节数；uint16 采样率（16000）；uint8 位宽（16）；uint8 声道（1） |
| 0x11 | AUDIO_DATA | F4→C3 | uint32 偏移 + 最多 512-4 字节 PCM。停等：每包等 ACK，超时 300 ms，最多 3 次 |
| 0x12 | AUDIO_END | F4→C3 | 空。C3 开始补 WAV 头并 POST |
| 0x13 | ASR_TEXT | C3→F4 | UTF-8，无结尾 0 也可，长度由 LEN 给出。空字符串表示没识别到 |
| 0x20 | CMD_WEATHER | F4→C3 | 空 |
| 0x21 | WEATHER_RESULT | C3→F4 | UTF-8 一行，例如 `多云 26°C` |
| 0x30 | ALERT_FALL | F4→C3 | uint32 Unix 时间，没有对时就填 RTC 的时分秒打包。C3 打一条日志或可选 HTTP，失败不影响本地蜂鸣 |
| 0x7E | ACK | 双向 | 空，SEQ 等于被确认帧 |
| 0x7F | NACK | 双向 | 1 字节错误码 |

错误码：`0x01` 超时，`0x02` CRC，`0x03` Wi-Fi 未连接，`0x04` HTTP 状态不是 2xx，`0x05` ASR 空结果，`0x06` 忙（上一包还没发完）。

C3 不保存表盘状态。它只记住：Wi-Fi 是否连着、最近一次天气字符串、正在拼的那一块 PCM。

### 5.3 C3 与云

板子侧协议到 ASR_TEXT / WEATHER_RESULT 为止。云厂商换掉时只改 C3。

**语音。** F407 上传的是裸 PCM。C3 在前面加 44 字节标准 WAV 头再 POST：

| 偏移 | 内容 |
| --- | --- |
| 0 | `RIFF` |
| 4 | uint32，文件总长 − 8 = 36 + PCM 字节数 |
| 8 | `WAVE` |
| 12 | `fmt ` |
| 16 | uint32 = 16 |
| 20 | uint16 = 1（PCM） |
| 22 | uint16 = 1（单声道） |
| 24 | uint32 = 16000 |
| 28 | uint32 = 32000（字节率） |
| 32 | uint16 = 2（块对齐） |
| 34 | uint16 = 16 |
| 36 | `data` |
| 40 | uint32 = PCM 字节数 |
| 44 | PCM |

短语音 REST 的 URL、Token 放在 C3 的 `secrets.h`，不要写进报告正文，报告里用“云端短语音接口，HTTPS，请求体为 16 kHz/16 bit/单声道 WAV，响应 JSON 中的文本字段”这种说法，并附一次真实返回（把密钥打码）。

**天气。** 见 4.4，C3 用 HTTPS GET。STM32 上不做 TLS。

Wi-Fi SSID 和密码同样只放 `secrets.h`。掉线后 C3 每 5 s 重连，并向 F407 发 HELLO_ACK（在线标志 = 0）。F407 据此把状态条改成「离线」，计步和时钟继续。

### 6.1 工程划分

任务（优先级数字越大越优先，LVGL 的全部调用只在界面任务里）：

| 任务 | 周期 | 优先级 | 事情 |
| --- | --- | --- | --- |
| 链路 | 50 ms | 高 | HELLO 心跳、发送天气请求和跌倒告警 |

| 传感器 | 20 ms | 低 | 读 MPU、计步，只在数字变化时投递事件 |
| 慢任务 | 1 s | 低 | RTC、DS18B20（转换完成才读）、在线状态 |

### 6.2 内存

【板级事实】F407 DMA 不能访问 CCM（`0x10000000`，64 KB）。内部 SRAM 从 `0x20000000` 起，128 KB，DMA 可用。

【方案约定】

| 对象 | 大小 | 放哪 |
| --- | --- | --- |
| PCM 缓冲 | 96000（3 秒）或 64000（2 秒） | 内部 SRAM。上了 40 行 LVGL 缓冲就用 2 秒 |
| LVGL 双缓冲 | 25600，必要时 51200 | 内部 SRAM，地址在 `0x2000xxxx` |
| UART4 RX | 600 | 内部 SRAM，DMA |
| LVGL 字体 | 界面用字，数 KB 到几十 KB | Flash `const` |
| 栈 | 启动文件里 ≥ 0x1000 | 内部 SRAM |
| 全屏图像 | 不分配 | LVGL 局部缓冲刷到 HX8357 |
| 大字库（可选） | 最多 1 MB | 外部 SRAM `0x68000000`。启用 F103 SPI 时不要改放 EN25Q128 |

链接脚本里若把大数组丢进 CCM，ADC DMA 会静默写错地方。地图文件里确认 `pcm_buf` 的地址在 `0x2000xxxx`。

### 6.3 主循环节拍

| 节拍 | 事情 |
| --- | --- |
| ADC DMA 中断 | 只搬数，录音满或松开后置标志 |
| UART 接收中断 | 把一帧丢进队列，优先级数值不低于 5 |
| SysTick | FreeRTOS 的 1 ms 调度节拍 |
| TIM6 | HAL 的 1 ms 时基，`HAL_GetTick()` 和 LVGL 的 tick 都读它 |
| 界面任务 | `lv_timer_handler()`，按键 |
| 传感器任务 | 读 MPU、计步 |
| 慢任务 | RTC、DS18B20（转换完成才读） |

录音的 3 秒内不要启动 DS18B20 的复位脉冲（PG9 的时序和优先级容易把主循环拖住）。温度在空闲态更新。

## 7. 演示脚本

1. 上电：表盘走时。晃动开发板，计步增加。状态条在 C3 连上 AP 后从「离线」变为「在线」，并出现表温。
2. 按住 K_UP，说「开灯」。松开后进度条走完，数秒内语音页出现识别文字，LED1 亮。
3. 说「现在几点」。屏上时间来自 RTC，此步不再请求天气。
4. 说「查天气」。通知页或语音页的结果区出现 `多云 26°C` 这种一行字。
5. 关掉路由器或让 C3 连一个不存在的 SSID：状态条变「离线」。再晃板子，计步仍增加，时钟仍走。再按 K_UP，语音页给出 `0x03`（Wi-Fi 未连接），灯保持原状。
6. 加分：手持板子向下顿一次，蜂鸣约 1 s，通知页出现跌倒。此步不依赖 Wi-Fi，拔掉 C3 的 TX 后蜂鸣和告警页仍然出现。

第 5 步是架构说明，答辩时主动做。

## 8. 风险与联调顺序

| 风险 | 表现 | 处理 |
| --- | --- | --- |
| 串口复用 | 打开 USART2 会碰到以太网 MDIO；打开 USART3 会碰到 RS232 和 WIFI 座 | 按 3.5、3.8，C3 只用 UART4，座子空着，TF 不插 |
| 音频太大 | C3 堆缓冲区或 HTTP 超时 | 3 s 上限，512 字节停等，460800 |
| USB 电流不够 | 一上传语音板子复位 | 火牛 5 V |
| 灯太暗 | 10 kΩ 限流 | 演示凑近，或口头说明原理图阻值，不要私自改成 1 kΩ 却在报告里写 10 kΩ |
| 两套固件一起调 | 问题分不清在 F407 还是 C3 | 严格按下面的顺序 |
| 字库 | 全字库进内部 Flash 会挤占程序 | MVP 只收界面用字 |
| PA5 没拔帽 | 录音是电位器的直流 | 先看 J01 |

联调顺序：

1. 只烧 F407：HX8357 点亮，LVGL 表盘走时，四键能翻页，秒针或进度条在局部更新。同时看主循环还能不能每 20 ms 读一次 MPU
2. 接上计步和 DS18B20，表盘数字会变。LED、蜂鸣按极性单独确认
3. C3 单独连热点，串口打印能 GET 到 Open-Meteo 的 JSON
4. 杜邦线接上 UART4，表盘从「离线」变为「在线」，查天气出现一行中文
5. 接麦克风，C3 侧看到的 PCM 长度约等于 `采样毫秒 × 32` 字节，再接云端识别，文字回屏后能开灯
6. 断网复测：计步和表温仍在，语音给出未联网

小游戏和 F103 不排进这个顺序。核心六步做完，再决定要不要加。

每一步都有一个与前后无关的通过标准，报告的“调试过程”按这个顺序写即可。

## 9. 写报告时可以直接改写的说明

下面是说明稿，不是实验记录。实测波形、识别率、步数误差上板之后再填，不要把约定值写成已经测到的结果。

### 9.1 系统概述（可放绪论或总体方案）

本设计在普中 PZ6808L-F4 上实现一个多功能 AI 手表原型。STM32F407ZGT6 用 LVGL 驱动 3.5 寸 HX8357，并在本地完成计步、表温和录音组包；ESP32-C3 只作为边缘网关，把音频和天气请求送到云端，再把云端返回的文字送回主控。语音识别使用云端现成服务，天气使用 Open-Meteo。开发板断网时，时钟、计步和表温仍由 F407 完成。板上的 F103 本阶段不使用；教程模块 33 的 SPI 短接只保留为算力不够时的后备。

### 9.2 器件与接口（可放硬件设计）

主控外部高速晶振为 8 MHz，RTC 晶振为 32.768 kHz，并备有 VBAT 纽扣电池。彩屏通过 FSMC 16 位总线连接，片选 NE4，基址 0x6C000000，命令/数据由地址线 A6 区分。六轴传感器 MPU6050 与 EEPROM 24C02 共用 I2C1（PB8、PB9），地址分别为 0x68 和 0x50。温度传感器 DS18B20 接在 PG9，板上上拉电阻为 10 kΩ。四只按键中，K_UP 接 PA0，按下为高；K1、K2、K3 接 PE2、PE3、PE4，按下为低。LED1/LED2 接 PF9/PF10，有源蜂鸣器经 PNP 接 PF8，三者都是低电平有效。

边缘网关不插入板载 ESP8266 座。该座的 UART 与 USART3、RS232 转换芯片处于同一对 TTL 网络，且脚序按 ESP8266 定义。C3 经杜邦线连接 F407 的 UART4（PC10 发送、PC11 接收），波特率 460800。与此同时 TF 卡不插入，因为 PC10/PC11 也是 SDIO 的 D2/D3。下载走板载 CH340 与 F407 的 USART1，切换端子停在 F4。

### 9.3 计步公式（可放软件设计）

加速度计量程 ±2 g。每 20 ms 读取三轴后计算合加速度

```
mag = sqrt(ax^2 + ay^2 + az^2)
```

再用一阶滤波跟踪重力基线，动态分量超过 0.15 g 后回落，且与上一步间隔不小于 300 ms，则记一步。阈值在实测走路与静止两组动作后确定，报告中给出最终取值和一段步数对比（例如走 50 步，显示值是多少）。

### 9.4 语音数据路径（可放软件设计或通信协议）

一次录音最长 3 s，格式为 16 kHz、16 bit、单声道 PCM，共 96000 字节，存放在 F407 内部 SRAM。DMA 不使用 CCM。数据按不超过 508 字节的载荷分包，从 UART4 发到 C3，每包等待应答。C3 补上 44 字节 WAV 头后，以 HTTPS 交给云端短语音接口，再把识别出的 UTF-8 文本送回 F407。F407 只做子串匹配：「开灯」「关灯」「现在几点」在本地执行，「查天气」再向 C3 要一次天气。Wi-Fi 不可用时返回错误码 0x03，本地计步不受影响。
